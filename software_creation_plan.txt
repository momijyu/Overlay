ソフトウェア開発演習 制作計画レポート

1. プロダクト基本情報

-   プロダクト名称：Overlay
-   本番公開環境URL：https://overlay-virid.vercel.app/
-   ソースコードリポジトリURL：https://github.com/momijyu/Overlay

2. 解決すべき課題と対象利用者

-   対象とする単一の利用者：大学の授業などで配布されたPDF資料に書き込みながら学習したい自分自身
-   切実な不便：PDF資料にメモを書き込みたい場合、PDFを直接編集できる環境が使いにくかったり、画像化して別のアプリに貼り付けたりする必要があり、資料とノートを一緒に管理するのが面倒である。
-   現在の代替手段とその限界：PDF編集ソフトやノートアプリを利用する方法があるが、ソフトのインストールが必要だったり、PDFへの書き込みとノートの管理が別々になったりする場合があり、手軽に利用しにくい。

3. 中核的価値

-   提供する決定的な価値：PDFをブラウザにアップロードし、そのPDFをそのままノートとして扱い、ペンやテキストで直接書き込める。元PDFと編集情報を分けて保存し、一覧から開いて編集を再開できる。書き込みを反映したPDFをローカルへダウンロードするまでの流れを、第4週までにv1.0.0として完成・公開する。

4. 技術スタックの選定理由と自習計画

-   フロントエンド：Next.js、React、TypeScriptを使用する予定。PDFの表示や書き込みなど、操作の多いWebアプリケーションを作成しやすいため採用する。UIにはTailwind
    CSSとdaisyUIを使用し、基本的なUI部品の作成を簡略化する。Next.jsについては未経験の部分もあるため、Reactとの違いや基本的なルーティング、データの扱い方を開発と並行して学習する。
-   バックエンドおよびデータ保存：第2週ではSupabaseのPostgreSQL・Storage・匿名認証を使用して保存を実装した。第3週の追加対応では公開サービスの保存容量と運用費を考慮し、通常のノート保存を各利用者のブラウザ内のIndexedDBへ変更する。PDFと線・階層を分離し、保存・取得・トランザクションを学習する。既存のSupabaseデータは削除しない。認証やDrive連携は開始指示まで保留する。
-   ホスティング環境：Vercelを使用する予定。GitHubと連携してWebアプリケーションを公開しやすく、Next.jsとの相性も良いため採用する。

5. 8週間の垂直スライス開発計画

第1週でMVPを公開し、第4週までに同じブラウザ・同じサイトで使う個人向けノートの初回完成版v1.0.0を公開する。第5週から第8週は、公開済みのv1.0.0に対する追加・改善の期間とする。サインイン画面と個人アカウント管理は第6週に残し、v1.0.0では複数端末からの再開を対象にしない。

2026年10月20日の最新方針：Chromeを主対象として制作・検証する。Safari対応は（仮・保留）としてv1.0.0の完成条件から暫定的に外す。Firefoxは補助的に互換確認を行う。Safariのタップ時の線幅・一覧開閉後の表示崩れは解決済みとはせず、時間に余裕がある場合に対応する。今回のUI整理では、まずノート一覧を左上のハンバーガーボタンで左から開くオーバーレイへ変更し、編集中は隠す。開閉でPDFの表示幅を変えず、既存の保存・階層操作を維持する。他のUIは続く指示に合わせて一つずつ整理する。

第1週：Webアプリケーションの基本環境を構築する。PDFをアップロードして表示し、ペンで書き込み、全ページの書き込みを反映したPDFをローカルへダウンロードできる状態で公開環境へ配備する。ダウンロードは再編集可能なノートの永続保存とは区別する。
第2週：Supabaseを接続し、元のPDFと書き込み情報を分離して永続保存できるようにする。保存データの所有者を区別するための匿名認証のみを使用し、同じブラウザで扱う識別情報とノートごとのIDを分けて管理する。Supabaseの管理画面で保存・更新を確認する。利用者の操作確認に基づき、ペンの太さ変更と表示倍率の変更も実装する。
第3週：保存済みノートを階層型のサイドメニューに表示し、ノート名から開いて編集を再開できるようにする。親を指定したフォルダ作成、ノート名・所属先変更、ノートとフォルダのドラッグ移動、フォルダ名変更、確認後の空フォルダ削除に対応する。自己・子孫への移動と同名衝突を拒否する。2026年10月15日の追加指示で、元PDFと線・階層を各利用者のIndexedDBへ保存する方式に変更する。まず手動保存・一覧・読み込み・更新と再読み込み後の保持を実装する。Supabaseの既存データは削除せず、移行・再編集用バックアップ・前回位置の自動復元・自動保存・スマホ実機確認は後続の作業へ分ける。メニュー全体も隠せるようにする。

第3週の追加方針（2026年10月15日）：ブラウザ内保存を維持し、必要なノートだけ既存のPDFダウンロードで個別に書き出す。OSの実フォルダへの直接保存や全体・フォルダ単位の一括ZIP出力は今回は作らない。PDF出力は閲覧・共有用で、編集データや階層を完全復元するバックアップではない。サイトデータ消失時にPDFから元の編集状態を完全復元できない制約を案内する。第3回の残作業として、最初の線の描画完了からの自動保存、保存状態、失敗時の再試行、切り替え時の保存待機、別タブとの更新番号の比較を実装する。保存中の追加描画を失わず、終了直前のイベントだけに頼らない。実装済みであり、スマホ・iPadを含む実機と公開環境の操作確認はこれから行う。付箋・目標は原型完成後の追加要素に回す。再編集用バックアップの追加時期・方式は未決定とする。

第3週の追加改善（同日・最新指示）：新規PDFは選択しただけでは保存せず、最初の描画完了から自動保存する。確認後のノート削除を追加し、元PDFとノート情報を同じトランザクションで削除し、途中の失敗なら両方取り消す。削除完了後の復元はできない。開いているノートは削除成功後に初期状態へ戻し、失敗時は編集内容を維持する。未選択時の操作メニュー案内、IndexedDB接続の再利用と切断時の再接続、Safari等の無アクセス期間によるデータ消去と定期的な個別PDF保管の案内を補完する。第4週の編集機能は含めない。

第4週：テキストの追加・内容と配置の編集・削除、ペンの色変更・線の削除、ペンとテキストの編集操作に対するUndo / Redoを実装する。テキストを含む編集情報の保存・再編集と、全ページのペン・テキストを反映したPDFのダウンロードに対応する。10月24日の計画追加と25日の開始指示により、単独ノート・フォルダ配下の編集用バックアップと復元も必須範囲へ追加する。既存ノートとの互換性、日本語テキスト、主要ブラウザ、失敗時の動作を確認・修正し、公開環境で一連の利用者シナリオを確認してv1.0.0を公開する。
第4週のバックアップ実装（2026年10月25日）：元PDF・確定済み編集情報・名前を、ノート1件またはフォルダ配下につき1つの.overlayファイル（無圧縮ZIP、schemaVersion:1）へまとめる。フォルダは子孫・空フォルダも含む。形式・破損・PDF・ページ参照を検証し、件数確認後に新しいIDで一番上へ復元する。同名の根フォルダには復元番号を付け、既存ノートは上書きしない。保存失敗なら全件取り消す。1回256MiB・200ノート・1000フォルダ等の安全上限を設ける。共有用PDFは維持する。OS実フォルダ直接保存・履歴復元・Google連携・自動同期は含めない。第3週の「個別PDFのみ」「バックアップ方式未定」よりこの指示を優先する。今回の実機・公開確認は別途行う。詳細はdocs/note-backups.md。
同日の補足指定：意図は選択したファイルをまとめてZIPで保存・読み込みすることと確認できたため、一覧の複数選択へ「ZIPで保存」を追加する。選択ノートとフォルダ配下を1つの.zip（schemaVersion:2、kind:selection）へまとめ、既存の読み込み確認からコピーとして復元する。親子の二重取り込みを避け、選択外は含めず、同名の根フォルダも復元時に衝突を回避する。全選択も使用できる。従来の.overlayは維持する。以下の全ライブラリ一括出力を対象外とした記述は専用機能を指し、全選択からのZIP保存は今回の範囲とする。第4回の完成条件にも含める。今回の実機・公開確認は別途行う。
第4週の追加指定（2026年10月20日・最新）：半透明のマーカーと、テキスト・付箋の文字色、付箋の背景色変更を追加する。マーカーは初期黄色・不透明度35%固定・5段階の太さで、色・太さを通常のペンと別に保持する。部分消去・自動保存・再読込・Undo / Redoと、継ぎ目が濃くならないPDF出力まで対応する。メモの色は直接入力欄でプレビューし、文章・文字サイズとまとめて確定する。キャンセルは元の色を維持し、色だけの変更では旧ボックスを自動サイズに変えない。元PDF・DBバージョン・保存先は変更せず、旧ノートも従来の見た目で開ける。以下の文字色を含めない記録はこの追加前の経緯とする。実ブラウザ・公開確認は別途必要。
第4週のUI整理（同日・続く指定）：利用者はマーカーの使用感を確認した。次に、ペン・マーカー・消しゴム・テキスト・付箋とUndo / Redoの表示をSVGの線画アイコンへ変更する。鉛筆・マーカー・消しゴム・枠付き文字・折り返しのある紙・左右の矢印で区別し、絵文字や外部画像は使わない。名前はホバー案内と読み上げ用に残し、選択中は背景・枠で示す。編集・自動保存・履歴の処理は変更しない。チュートリアルページは後の検討事項であり今回は作らない。今回変更後のChrome・公開確認は別途行う。

第4週の着手順（2026年10月19日）：ユーザー指示により、まずペンの色変更と部分消去から進める。削除方式は線を丸ごと消すのではなく、触れた部分で線を分割して残りを維持する方式とする。色・消去結果のローカル保存・再表示・PDF出力までを最初の単位とし、操作確認を挟んで次へ進む。この単位ではテキストとUndo / Redoを実装せず、第4週全体の完了とも扱わない。
第4週の次の単位（同日）：ユーザーによるペン編集までの検証・内容確認の報告と継続指示を受け、ペン描画・消去のUndo / Redoを追加する。1操作ごとの取り消し・やり直し、操作順と対象ページの復元、変更結果の自動保存を確認する。履歴は開いているノートの直近100操作をメモリ内に保持し、切り替えや再読み込み後には持ち越さない。テキストとその履歴への接続は次の単位へ分ける。今回の実ブラウザ確認と第4週全体の完了確認は未完了。
第4週の追加単位（2026年10月20日）：ユーザーの指示でテキストボックスと付箋の2種類を今回へ追加する。最新の指定で両方ともPDF上の直接入力へ統一し、各追加ボタンか空白クリックで設置、選択枠で移動する。手動リサイズは廃止し、小〜大の文字サイズスライダーと任意の数値指定で調整する。付箋の背景は維持する。箱は文字に合わせて自動調整し、外側クリック・完了で文章と文字サイズをまとめて確定・自動保存する。キャンセルと未確定の草稿を分ける。仮の外観で追加・文章編集・移動・文字サイズ変更・削除、ローカル保存・再編集、ペンと混在したUndo / Redo、日本語を文字として選択・検索できるPDF出力まで実装する。旧ノートを維持し、日本語フォント・追加ライブラリの役割を説明する。デザインは第4週の最後に整理し、今回の実機確認・公開反映はまだ完了として扱わない。文字色・見出し・分類・空白ページ・認証は含めない。
第5週：2026年10月26日の指示で開始する。まず第4週から持ち越した依存の脆弱性対応と公開環境でのZIP保存・復元・再編集・開き直し・PDF出力を確認する。続いてページIDと表示順を分け、元PDF・既存の書き込み・旧ノートとの互換性を維持する。現在のページの直後に同じ表示サイズ・向きの空白ページを挿入し、そのページへ移動する。空白ページへの編集・自動保存・Undo / Redo・バックアップ・PDF出力も確認する。ページ見出しは必要なページだけに追加・変更・削除でき、一覧から直接移動できるようにする。入力UI・PDF出力への反映は実装前に確認し、分類等は自動追加しない。

第5週のGoogle Drive連携（同日追加）：未連携なら従来のIndexedDB保存、連携後は利用者自身のDriveを保存先、IndexedDBをキャッシュ・未送信内容の保護に使う。Drive内のOverlayフォルダ以下へ階層・元PDF・編集情報を分けて管理する。既存ローカルノートのアップロード対象は確認し、無断で全件を送らない。接続・読み込み・保存に続いて、編集確定後の待機・直列保存、失敗時の保持・再試行、競合時の上書き防止、アカウント切り替えを検証する。OAuth方式・Google Cloud設定・最小限の権限は実装段階で確定する。アプリ終了後の常時同期・共同リアルタイム編集・第6週のアプリ独自アカウント管理は含めない。PC・スマホ・iPadで一連の操作を確認する。第4週の完成判定と第5週の進捗は分け、詳細はPROJECT.mdとdocs/phase5-checks.mdへ記録する。

第5週の容量対策・先行改善（2026年11月4日）：Drive連携中はDriveを正式な保存先とし、再取得可能なPDF・編集本文だけに初期500MBのキャッシュ上限を設ける。未送信・失敗・競合中・編集中・ローカル専用のデータは自動削除しない。接続切れでローカル専用保存へ自動変更しない。SQLiteへの置換は行わず、PC・iPadでの共通利用を優先する。ページ機能の前に一覧の読み取り負荷を改善するため、IndexedDB版2に一覧専用のnoteSummariesを追加し、保存・整理・削除・復元と原子的に更新する。旧PDF・編集本文は変更せず、移行失敗時は取り消す。キャッシュ削除とDrive連携はまだ実装していない。OAuthクライアントIDは未作成のため設定手順を用意し、認証方式の確定と接続・保存の実装へ進む。詳細はdocs/drive-storage-plan.mdとdocs/google-drive-setup.md。
第5週の続く認証準備（同日）：ユーザー回答により、GIS token modelのブラウザ完結方式へ決定した。Google SDKの明示読み込み、最小限のdrive.file権限、メモリ内だけのトークン保持、期限切れ・拒否・キャンセル・再試行を扱う内部処理とテストを追加する。期限切れ時は利用者が再接続する。シークレットや更新トークンをサーバー・ブラウザへ保存する方式は今回採用しない。通常UIとDrive保存にはまだ接続せず、認可成功と保存完了を区別する。Google側の設定後に実接続・アカウント確認・保存の実装を進める。

第5週の続く接続確認（同日・最新）：ノート一覧からGoogleアカウントと専用フォルダを確認する画面を追加する。Google SDKは確認画面を開いた後だけ読み込み、認可は準備後のクリックから開始する。専用フォルダは本人所有・アプリの目印を検証し、未作成なら明示操作で作る。同名の一般フォルダや複数の専用フォルダは自動採用せず、閉じると通信・認可を破棄する。この段階ではローカルノートを送らず、保存先はIndexedDBのままとする。ノートのDrive保存・読み込み・未送信保護との接続・500MB整理は後続。上書きの競合制御は公式APIの条件付き更新を検証してから接続する。実Google・PC・iPad・公開環境の確認は別途行う。

第5週の続く保存・読込（同日・最新）：利用者がOAuth・テストユーザー・Drive APIを設定し、Chromeのlocalhost:3000で認可・本人情報・専用フォルダを確認した。続く指示により、ノート1件を確認後にDriveへ新規保存し、Drive一覧からブラウザへ別ノートとしてコピーする単位を実装する。元PDFと編集JSONをノートごとのコンテナへ分離し、最後のJSON完了後だけ一覧へ載せる。一覧は50件単位、本文は選択時に取得する。コピーは既存の復元確認で承認後だけ追加し、元データを変えない。通常の自動保存先はまだIndexedDBで、Drive正式保存への自動切り替え・既存ノート更新・送信待ちDB・500MB整理は後続とする。今回の実Google送信・コピー・他端末・iPad・公開確認は未実施。制約・手順はdocs/google-drive-notes.mdへ記録する。
