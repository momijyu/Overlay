# Google Driveの保存・読み込み

現行のDrive仕様をこの資料へ集約する。事前設定は[Google Cloud設定](google-drive-setup.md)、利用手順の概要は[README](../README.md)、比較計測は[速度改善](drive-performance.md)を参照する。

## 接続と通常操作

1. ノート一覧下の「Google Drive」欄で「接続設定」を開き、「Googleで接続」から認可する。接続先はメールアドレスで確認し、氏名は表示しない。
2. Overlay専用フォルダを確認する。未作成なら「専用フォルダを作成」を実行する。同名の一般フォルダを流用しない。
3. 接続確認後、全ローカルノート・空フォルダを自動保存対象へ登録する。ノート別の有効化操作は不要。閲覧で取得しただけのキャッシュは、別ノートの保存・再接続で送信対象にしない。
4. 同じアカウントで別端末から接続すると、共通一覧と付箋索引を取得する。ノート名を押す時だけ、必要な版のPDFと編集本文を取得する。異なる編集がある場合はDrive保存日時・このブラウザか別のブラウザかを確認して「今後使う内容」を採用する。採用の送信が終わると他端末でも共有される。
5. 「Drive一覧を更新・再試行」で更新や失敗後の再試行を行える。接続中は約30秒ごとにも共通一覧を確認する。未接続・認可失効中は未送信内容を端末に保護し、再接続後に再開する。

一覧で選んだフォルダを新規PDFの初回保存先とする。ノートを選んだ場合はその所属先、未選択または「一番上」ならルート。追加先が削除された場合に勝手に別の場所へ保存しない。

## 保存構成と識別

```text
Overlay/
  2026/
    情報/
      ノート1/                  共通の論理ノートと物理フォルダID
        ノート1 (端末番号)/     端末ごとの編集版
          元PDF.pdf
          ノート1.overlay.json
  .overlay-stickies-保存先ID.json  端末別の軽い付箋索引
  .Overlay管理-端末番号/       階層変更の不変の履歴
    .overlay-tree-ID.json
```

名前やパスではなく、論理ID・親ID・Driveの物理IDで対応付ける。改名・移動は既存IDを維持し、同じノートを新規作成し直さない。共通階層の履歴は本文と分離し、PDFを複製しない。従来の手動保存はOverlay直下のノートフォルダにPDFとJSONを持つ別形式で、名前だけで自動保存ノートへ結合しない。

自動保存はJSON版4（sync-note）。元PDFを変更せず、線・マーカー・文章・色・白紙の構成・表示順と旧見出しデータをJSONへ保存する。手動形式の旧版1〜3も検証して読み込む。専用appProperties・所有者・保存場所・ID・PDF参照・サイズ・世代・内容ハッシュ・チェックサムを確認し、表示名だけで別ファイルを読み込まない。

Drive上の管理フォルダ・JSONは手動で移動・編集・削除しない。想定外の変更・権限喪失・欠落はエラーで止め、別の実体を勝手に作って埋めない。複数のOverlay専用ルートがある場合も自動選択・統合・削除をしない。必要なデータを書き出して保存場所を確認する。

## 自動保存と失敗時の保護

- 編集の確定をまずIndexedDBへ保存してからDriveへ送る。通常は最後の編集から2秒後、最大10秒の待機とし、タイマー約1秒・通信時間は別。保存中も編集入力を止めない。
- 元PDFは初回に送り、以降の通常編集はJSONだけ更新する。名前・階層の変更も未送信状態と同じトランザクションで記録する。
- 送信前のJSONが既知の全バイトチェックサム・サイズと一致する場合は本文の再取得を省く。送信後は別のメタデータ取得で実体を再確認し、送ったJSONのチェックサム・サイズとの一致を検証する。チェックサム未提供・未知の本文・旧保存情報では従来の取得・形式・世代・内容ハッシュ検証へ戻る。DBの送信情報へuploadedChecksumとuploadedJsonBytesを追加するが、DB版・Drive形式は変更せず、旧データは未設定として扱う。
- 送信完了は取得した更新番号までのみ記録し、送信中の追記を送信済みにしない。待ち行列へ本文・PDFのコピーを作らない。
- 通信断は2〜60秒へ待機を増やして再試行。認可失効・権限エラー・競合等では停止し、接続または内容の確認を求める。
- 初回作成用IDはGoogleの予約IDを取得し、送信前に端末へ記録する。成功応答を失っても同じIDを検証し、重複作成を防ぐ。JSON更新の結果不明時も世代・ハッシュで確認する。
- 同じブラウザの複数タブはWeb Locksで直列化する。認可やアカウントが変わった古い応答を採用しない。削除済みノートを遅い通信結果で復活させない。
- ブラウザ終了後・スリープ中の送信は保証しない。未送信は次回の再接続後に再開する。終了警告は対応ブラウザの補助であり、強制終了まで保証しない。

Google認可はメモリ内で有効期限まで再利用する。再読み込み・失効後は利用者の操作で再接続し、トークンを永続保存して期限を無制限に延ばす設計にはしない。

設定画面と自動保存は同じページ内の接続を共有し、開発中に接続モジュールが再評価されても分離しない。認可の失効・切断を購読者へ通知し、設定画面も5秒ごとに期限を確認する。失効後は古いアカウント・保存先を接続済みとして表示しない。OAuthクライアントIDが変わった場合は旧認可を破棄して確認し直す。修正前のページで表示が食い違っていた場合は、端末への保存完了を確認してページを再読み込みし、「Google Drive」から再接続する。サイトデータの削除は不要。

## 未取得資料の付箋

PDFを開く前にも、Driveにある資料の付箋を一覧化する。本文とは別の固定IDの索引を、約30秒ごとの一覧確認に合わせて背景更新する。先頭行・ページID・付箋IDと端末別の保存先だけを持ち、通常の索引表示ではPDF・編集本文を取得しない。索引のない旧資料だけは1周期4件まで編集JSONを検証し、PDFを取得せず参照を生成する。

索引の通信失敗で本文送信は停止しない。編集中・未送信の付箋は端末側を優先し、削除済み資料は索引が残っていても復活させない。複数版は付箋から選んだ版を開く。索引の反映は本文送信より遅れる場合があり、移動時に実在する付箋を再確認する。[形式・上限と互換](sticky-outline.md)

## 競合

通常の同時編集を主用途としなくても、古いタブ・端末の使い分け・外部変更は起こり得る。安全確認を省いて高速化しない。

本文は端末ごとに書込先を分け、同じ論理ノートは一覧で1件にまとめる。異なる編集がある時は「今後使う内容を選択」で採用する。画面にはDrive保存日時と、このブラウザ／別のブラウザ・端末の保存先を表示し、生の端末IDは出さない。日時はDriveへの保存日時であり、最後に文字を書いた時刻とは限らない。

採用時に確認した全保存先の版番号・提供される内容チェックサムと、以前の採用履歴を、不変の管理イベントへ記録する。取得・検証した本文と採用イベントは同じIndexedDBトランザクションで保存し、通常の待ち行列からDriveへ公開する。公開が終わるまで他端末へ反映済みとは扱わない。キャンセル・取得失敗・未送信編集がある場合は採用しない。選択中に内容・採用履歴・認可・接続先が変わった場合も古い結果で上書きしない。

採用済みの旧版は通常の選択対象から外し、別端末でも同じ確認を繰り返さない。採用した本文を別端末で編集すると、その基点のチェックサム・採用履歴を記録した続きとして扱う。基点が変わっていなければ続きを選択対象とし、並行した続き・旧版への新しい編集・複数端末で異なる採用があった時は再確認する。時刻だけで新しい方を勝手に採用しない。

選ばなかった編集JSON・PDFを削除せず、物理ファイルの一括上書きや線・文章の自動統合はしない。採用版の通常編集は従来通りその端末の保存先を更新するため、全操作の永久バックアップではない。キャッシュ表示後に別の採用や変更を検出しても、編集中の本文は自動置換せず案内する。

Driveのversionは本文以外の変更でも増えるため、番号差だけを編集競合と扱わない（[Google公式のFiles仕様](https://developers.google.com/workspace/drive/api/reference/rest/v3/files)）。自端末の送信済み版について、番号差がある時だけ確認する。既知の全バイトチェックサム・サイズが一致すれば本文取得は不要。それ以外は上限16MiBのJSONを取得し、端末・世代・PDF参照と再計算した内容ハッシュを照合する。一致すればキャッシュの確認版だけ進める。本文・PDF・ローカル更新番号・送信済み状態は変更しない。本文が異なる場合の警告、取得失敗の案内、確認中に編集・接続先が変わった場合の古い結果の拒否は維持する。通常の版一致時はJSON・PDFを追加取得しない。

階層は単一の共有JSONを上書きせず、以前の変更IDを参照する不変イベントを作る。同じ基点からの名前・配置の変更は分岐として検出し、確認画面で選択後、両方の変更を参照する合流履歴を追加する。確認後の再変更は選び直す。削除を含む競合、異なるIDの同名フォルダ、循環・移動先欠落は自動解決しない。

Driveの複数ファイル更新は原子的ではない。不完全な新規履歴の取得時は現在の一覧を維持し、間隔を延ばして再取得する。既知の公開済み履歴の消失はエラーとする。固定ID・変更履歴から途中の移動を再試行するが、全端末の同時操作や外部からの直接改変を完全にロックする保証はしない。

## キャッシュ・雲・削除

| 項目 | 現行仕様 |
| --- | --- |
| 初期上限 | 250MB（1MB = 1,000,000バイト） |
| 設定範囲 | 100〜1,000MBの整数。スライダー／数値入力後に適用。このブラウザだけに保存 |
| 未使用保持 | 原則30分。使用を終えた時点から数える。上限超過時は猶予時間内でも古いものから整理 |
| 整理しない内容 | 使用中・他タブ使用中・未送信・保存失敗・ローカル専用 |
| 雲 | 端末にPDFと編集本文がそろわず、Drive取得が必要なノートのみ |

送信・取得を確認できた再取得可能なPDF・編集本文だけを整理する。小さな一覧・階層履歴・未送信情報は残す。保護対象とブラウザ内部のオーバーヘッドは上限の対象外であり、ブラウザの全使用量を設定値以下に保証しない。キャッシュのないノートはオフラインでは開けない。使用中保護のロックが取れない環境では自動整理しない。

端末に本文とPDFがある場合は、Driveにも保存されていても雲を出さない。送信待ち・失敗等は既存の状態案内で示し、雲の有無だけで送信完了を判断しない。

アプリ内での削除は共通一覧にも反映するが、Drive上の元PDF・編集JSONを自動でゴミ箱へ移さない。キャッシュ整理も一覧やDrive実体を削除しない。Drive自体の容量が減る操作と混同しない。

## 手動保存・以前のバックアップの復元

Drive画面では接続アカウントと保存先を短く表示する。内容部分だけをスクロールし、画面下の閉じる・再接続操作は固定する。

既存の手動操作は、自動保存とは別に保管するバックアップとして残す。一覧の「操作 → Driveにバックアップ」、複数選択の「Driveにバックアップ」から対象を渡し、保存先の確認後に送信する。フォルダ選択では選択された子ノートを対象にし、手動一括保存自体は階層・空フォルダを複製しない。通常の自動階層連携と区別する。

- 上限200ノート。確認画面に新規／上書きと対象を出す。同名タイトルが複数ならID付き保存名で区別し、無条件に中断しない。
- PDFと本文を1件ずつ取得・直列送信。全PDFをまとめてメモリへ読み込んだりZIP化したりしない。
- 同名上書きは確認時と送信直前の版・所有者・参照を再検証する。同じPDFのサイズ／SHA-256が一致すればJSONだけ更新する。不一致等では新PDFへ参照を切り替え、旧PDFは自動削除しない。
- 4MiB以下のJSONはmultipart（メタデータ変更不要の更新はmedia）、元PDF・4MiB超のJSONはresumable送信。PDF成功後だけJSONを送る。Googleの小さいファイル向け5MBを下回る範囲を使い、追加したJSONも1リクエスト単位の成功・失敗として扱う。[Googleの送信方式](https://developers.google.com/workspace/drive/api/guides/manage-uploads)
- 失敗時は後続を止め、成功分は残す。「残りの保存先を確認」で未完了分だけ確認し直せる。閉じると手動処理を中断するが、成功済みは戻さず、処理中の結果が不明な場合はDrive一覧で確認する。再読み込み後の手動進行は復元しない。
- 手動上書きの最後の確認と更新は原子的ではないため、同時保存を避ける案内を維持する。これを通常の自動保存へ流用しない。

通常のDrive設定から重複する一覧・コピー操作は外した。クラウドの資料は通常のノート一覧から開く。以前の手動保存分は「編集用バックアップを読み込む → Driveの手動バックアップから復元」を選んだ時だけ一覧を取得する。「更新」「さらに表示」は維持し、PDF・本文は「復元」を押した分だけ取得する。保存日時で区別し、生の端末IDは表示しない。通常の自動保存・共通階層・付箋索引は別処理として継続する。

以前のDriveバックアップは確認後に新しいローカルノートとして復元し、元を上書きしない。同じPDF全バイト・線・文章・ページ構成・旧見出しがある場合は追加しない。名前・所属・IDだけで重複を決めない。候補を1件ずつ確認し、PDFは1MiBずつ比較する。別タブの変更で比較結果が古くなれば中止する。ZIP/.overlayからの通常復元は別操作で、コピーを追加する。

## 構成・安全上限

IndexedDB版7。driveBindingsとdriveSettingsで送信状態・端末識別・設定、driveEntitiesとdriveTreeEventsで共通ID・階層・版参照・キャッシュ・履歴を保持する。版更新で既存PDF・本文・送信待ちを削除しない。トランザクション内で通信やPDF解析を待たない。

| ファイル | 担当 |
| --- | --- |
| googleIdentity.ts / googleDriveAuth.ts / googleDriveSession.ts | SDK準備・認可と接続先のメモリ保持 |
| googleDriveClient.ts / googleDriveNoteData.ts / googleDriveNotes.ts | 制限付きHTTP・形式検証・手動保存／取得 |
| driveLibraryData.ts / driveLibraryLocal.ts | 階層の検証・分岐・ローカル一覧と送信待ち・配置競合 |
| driveVersionData.ts / driveVersionRemote.ts | 本文の採用履歴・編集の引継ぎ・候補とメタデータ検証 |
| driveLibraryRemote.ts / driveLibraryRuntime.ts | 固定ID準備・履歴取得と公開・フォルダ移動・背景処理 |
| driveStickyIndexData.ts / driveStickyIndexRemote.ts / driveStickyIndexLocal.ts | 付箋索引・未取得資料の一覧・旧本文からの参照生成 |
| driveAutosave.ts / driveAutosaveRemote.ts / driveOutbox.ts | 端末別本文の送信・再試行・更新番号 |
| driveLibraryCache.ts / driveCacheChecks.ts / driveCacheSettings.ts | 必要時取得・使用中保護・整理・背景版確認・容量設定 |
| googleDriveBatch.ts / noteDuplicates.ts | 手動一括保存・コピー復元の重複判定 |

今回の追加はIndexedDB版7・階層イベント版1の省略可能な項目を使用し、初期化・依存追加は行わない。古いアプリのタブは採用イベントを解釈できない場合があるため、利用する端末のOverlayを更新してから使う。

1PDF256MiB、編集JSON16MiB。本文の採用確認は1ノート100保存先まで、履歴の直接参照は32件まで。階層履歴1件64KiB・100項目、履歴10,000件・物理フォルダ20,000件・階層100段などの上限で停止する。これは使用メモリの保証値やキャッシュ上限とは別。1ブラウザで同時に連携するのは1アカウント・1専用ルート。別アカウントへ既存の未送信データを転送しない。

大規模ライブラリの差分取得・履歴圧縮／削除は未実装。検証を省かず、実測から追加の必要性を判断する。実Google・iPad・公開URLの通し確認と一般利用向け設定は[第7回の引継ぎ](phase7-checks.md)へ記録する。

Google公式参照：[drive.file](https://developers.google.com/workspace/drive/api/guides/api-specific-auth)、[token model](https://developers.google.com/identity/oauth2/web/guides/use-token-model)、[予約ID](https://developers.google.com/workspace/drive/api/guides/manage-uploads#use_a_pre-generated_id_to_upload_files)、[アップロード](https://developers.google.com/workspace/drive/api/guides/manage-uploads)、[フォルダ移動](https://developers.google.com/workspace/drive/api/reference/rest/v3/files/update)。
