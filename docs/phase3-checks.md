- [ ] フォルダ名だけでなく直下のノート・内部の余白でも移動でき、子フォルダが優先される。最上位のノート上なら最上位へ戻る。強調された範囲と移動先が一致する。
- [ ] 選択欄からのフォルダ移動もでき、Safari・Chrome・Firefoxで確認する。
- [ ] フォルダ選択後の作成先がそのフォルダになり、「最上位」を選べば最上位に作成できる。
- [ ] 「操作」から選択中の項目を変更でき、モーダルをキャンセル・Esc・背景クリックで閉じた後も一覧のクリックとドラッグができる。
- [ ] モーダルの保存中は閉じられず、失敗時は入力とエラーが残り、成功時は閉じて一覧を更新する。
- [ ] 閉じたフォルダと現在の親の上でドラッグしたまま待つと開き、中の子フォルダへ移動できる。途中で離れると展開しない。
- [ ] 320px幅の一覧で同じ親の名前位置がそろい、子は20pxずつ字下げされ、縦のガイド線で親子関係を確認できる。空フォルダに余分な子行や線が出ない。
- [ ] 左の開閉マークで開閉状態を見分けられ、長い名前も折り返さず、ポインターを重ねると全体を確認できる。

- [ ] 開いているノートの保存先が一覧下部に表示され、移動後の再取得で新しい場所になり、別フォルダを選択しても開いているノートの保存先を示す。
- [ ] 移動成功の表示が3秒後に消え、移動の失敗理由は消さずに残す。
- [ ] 選択中のノートが通常背景と見分けられる灰色と通常の文字色になり、他のメニューの選択色は変わらない。薄すぎるとの利用者の指摘を受け、背景色80%・文字色20%の混色に調整した。調整後の見た目は未確認。
- [ ] 修正後の移動用SQLと管理用SQLを実Supabaseへ適用し、同じ定義の再実行も成功する。
- [ ] 「操作 → 名前変更」でフォルダ名と保存先表示が更新され、子・ノート・PDF・線は変わらず、再読み込み後も名前が残る。
- [ ] 同名・空白・変更なしの名前では送信できず、キャンセルと通信失敗でも元の名前を維持する。
- [ ] 空のテスト用フォルダだけが削除可能になり、対象名と確認を表示する。キャンセルでは残り、削除後は親や他のデータが変わらない。
- [ ] 確認画面の表示後に別タブで子を追加した場合も、DBが削除を拒否する。削除中は二重送信・閉じる操作・PDF切り替えを止め、失敗時は確認画面と理由を残す。

前回の幅256px・横線付きの表示は、利用者のスクリーンショットで名前の省略と補助線の多さが分かりにくいことを確認した。今回の幅320px・縦線だけの表示は本番ビルドで生成できているが、変更後の実ブラウザでの見た目・省略表示・保存先表示・成功表示の自動消去は未確認。HTMLとイベントのテストだけで視覚的な確認を完了にしない。

識別情報の消失は仮のAPIでテストしている。確認のために実際のブラウザのサイトデータを削除しない。匿名の識別情報を失うと、保存済みノートへ再アクセスできなくなる。

## ノートの形に関する指定

ユーザー指定のVS Codeのような階層型サイドメニューに変更した。フォルダと子を開閉でき、ノート名を直接押して開く。各ノートの「開く」ボタンは削除し、メニュー全体も隠せる。フォルダ作成と保存済みノートの名前・所属先変更に加え、ノート・フォルダのドラッグ移動を追加した。今回の第3回補完で、同名衝突の事前判定・フォルダ名変更・確認後の空フォルダ削除を追加した。子要素があるフォルダの削除と手動の並び替えは対象外。

第4回のテキスト、削除、Undo / Redoなどには着手していない。
