# ページの追加・削除

現行IndexedDBは版7。ページ構成は版3で導入した固定ページIDを使用し、元PDFを保持する。今回の変更でDBの形式更新や初期化は行わない。

## 操作

ページ送りと間隔を空けた独立ボタン「ページ操作」から選ぶ。スマホ・iPadでもボタンの文字を表示し、操作一覧と確認画面はツールバーに隠れないダイアログで開く。

- **次に白紙追加**：現在のページの直後へ、同じ表示サイズ・向きの白紙を1枚挿入して移動する。白紙の後・末尾にも追加できる。回転PDFでは回転後の表示サイズを使い、白紙そのものの回転は0度とする。
- **ページを削除**：表示中の元ページまたは白紙と、そのページの書き込みを確認後に除く。次のページへ移動し、末尾を削除した場合は前のページへ移る。最後の1ページは削除できない。
- **書き込みを一括削除**：表示中ページだけの線（マーカー含む）・付箋・テキストボックスを種類別に選ぶ。種類ごとの件数と合計を確認して削除する。元PDFの内容・別ページ・選ばなかった種類は消さない。対象がない種類は選択できない。

削除のキャンセル・Escape・背景クリックでは内容を変更しない。確認中に対象資料や編集内容が変わった場合も削除を止め、再確認を求める。

追加・削除だけでも自動保存を開始する。Undoでページ追加を取り消すと挿入元へ、ページ削除を取り消すと元のページと書き込みを復元してそのページへ移動する。複数種類の一括削除も1操作で取り消せる。Redoにも対応する。履歴は既存と共通の直近100操作で、ノート切り替え・再読み込み時にリセットする。ノート／フォルダ自体の削除はこのUndoの対象ではない。ページの並び替えは追加しない。

## 保存するデータ

元PDFのBlobは変更しない。`pages?: NotePage[]`に表示順を持つ。

```ts
[
  { id: 1, kind: "pdf", pageNumber: 1 },
  { id: 4, kind: "blank", width: 600, height: 800 },
  { id: 3, kind: "pdf", pageNumber: 3 },
]
```

元PDFが3ページの場合、この構成は元の2ページ目を除き、1ページ目の次に白紙を追加した状態を表す。画面の2ページ目はID 4で、書き込みは`strokesByPage[4]`・`textsByPage[4]`へ保存する。元の3ページ目は表示順が変わってもID 3のまま。残したページの書き込みを移動・複製しない。

元ページは残す分だけを元の順序で1回ずつ含める。すべての元ページを除き、白紙だけを残すこともできる。白紙IDは元ページ数と現在のIDの最大値＋1を使い、削除した元ページのIDと重ならないようにする。Undo／Redoは同じIDを復元する。旧ノートは`pages`がない場合に元PDF順と解釈し、開いただけでは保存内容を変換しない。

合計10,000ページまで。白紙の各辺は0より大きく14,400ポイント以下とし、それを超える表示寸法のページからの追加はエラーで停止する。空の構成・重複ID・元ページの並び替え・不正寸法・構成にない書き込みIDを拒否する。PDF解析時には実際の元ページ数と元ページ番号の範囲、白紙IDとの衝突も照合する。

ページ削除では対象IDの線・文章・旧見出しを構成と一緒に除く。一括削除では選んだ種類だけを変更し、旧見出しは維持する。

## 保存・書き出しとの接続

| 経路 | 内容 |
| --- | --- |
| IndexedDB | 線・文章・ページ構成を同じ更新番号／トランザクションで保存。元PDFは初回だけ保存する。 |
| 自動保存 | ページ追加・削除と一括削除もDirtyとし、保存中のUndoや追記は次のスナップショットへ送る。失敗時は内容・履歴を残して再試行できる。 |
| 単体／フォルダ／選択ZIP | 既存のページ構成付きバックアップ（版3／4）へ保存。元PDFと編集情報を保持し、コピーとして復元する。旧版1・2も読み込む。 |
| Drive | 既存のページ構成付き編集JSON（版2以降）へ保存し、再取得・コピーでも削除後の構成を保持する。認可・競合・未送信保護は変更しない。 |
| 重複判定 | 白紙の配置・寸法と残した元ページも判定へ含め、異なる構成を同じノートとしてスキップしない。 |
| PDFダウンロード | 出力用PDFから除いた元ページを外し、白紙を挿入して残したページIDの線・文章を描く。未記入の白紙も含む。元PDFのBlobは変更しない。 |

元ページの全件保持を前提とする古いアプリでは、削除後の構成を不正として拒否する場合がある。端末間・バックアップの受け渡しには更新版を使う。サイトデータの削除・手動初期化は不要。

未連携時はブラウザ、連携後は[Drive保存](drive-storage.md)を利用する。元PDFはUndo・元ページ参照のため保持するので、ページを除いても元PDF本体の保存容量は減らない。

## コードの役割

- `notePages.ts`：ページ構成、サイズ・ID・元ページ順と書き込み先の検証、挿入・削除。
- `PageActionsMenu.tsx`／`PageEditDialog.tsx`：ページ操作の入口、種類・件数・削除確認とキャンセル。
- `PdfWorkspace.tsx`／`PdfPage.tsx`：表示順と固定IDの変換、白紙描画、確認時の対象照合と履歴・保存への接続。
- `strokeHistory.ts`：ページと書き込みの操作前後を一括記録し、Undo／Redoで復元する。
- `localAutosave.ts`／`localNotes.ts`：ページ構成と書き込みを自動保存・再読込・復元へ含める。
- `noteBackupData.ts`／`noteBackupFile.ts`／`googleDriveNoteData.ts`：既存のバックアップ・Drive形式でページ構成を検証する。
- `exportAnnotatedPdf.ts`：元PDFを保持したまま、出力対象ページを絞り、白紙と書き込みを追加する。

## 確認記録

11月10日、全768件の自動テスト・lint・型チェック・隔離コピーのwebpack本番ビルドが成功。仮DB・仮Driveデータと実PDFの解析で、元ページ／白紙の削除、最後の1ページ、固定ID、種類別一括削除、Undo／Redo、保存失敗、旧データ・バックアップ・Drive形式との接続を確認した。

専用Chromeの一時プロファイル・別ポートで、自作PDFへ線・付箋・テキストを追加し、キャンセル、一括削除・Undo、ページ削除・Undo／Redo、再読み込み・再表示、削除後のPDF出力を確認した。320×700、390×844、844×390、820×1180、1180×820で確認ボタンの44px以上の寸法とヒット判定、画面内の配置を確認した。利用者の保存データ・通常の3000番サーバー・実Driveは操作していない。

実スマホ・iPadの指／Apple Pencil・ソフトキーボード、Safari、実Google Driveの送受信と公開URLの通し確認は残す。テスト用ノートでページ追加・削除・一括削除→保存待ち解消→別端末で通常一覧から開く→PDF／バックアップ出力・復元を確認する。
