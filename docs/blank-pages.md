2026年11月5日の追加で、現在のDB版は5。付箋一覧用の参照を再生成し、既存PDF・本文・独立した見出しは保持する。[付箋一覧](./sticky-outline.md)。以下の旧版への記述は機能追加時点の記録。

続くページ見出し対応により、現在のDB版は4。見出し付きバックアップは版4・Drive JSONは版3を使い、本文の白紙のみの形式も継続して読み込む。[ページ見出し](./page-headings.md)。以下のDB版3は白紙追加時の更新記録。

## 操作

PDFを開き、ページ切り替え横の「紙に＋」ボタンを押す。読み上げ名とホバー案内は「次に空白ページを追加」。現在のページの直後へ、同じ表示サイズ・向きの白紙を1枚挿入して移動する。白紙の後・末尾にも追加できる。回転PDFでは回転後の表示サイズを使い、白紙そのものの回転は0度とする。

追加だけでも自動保存を開始する。ペン・マーカー・部分消去・テキスト・付箋は通常ページと同じ操作。Undoで追加を取り消すと挿入元へ、Redoで同じ白紙へ移動する。白紙に書き込んだ場合は、書き込みを戻してから挿入を戻す。履歴は既存と共通の直近100操作で、切り替え・再読み込み時にリセットする。一般のページ削除・並び替えは今回追加しない。

## 保存するデータ

元PDFのBlobは変更しない。`pages?: NotePage[]`に表示順を持つ。

```ts
[
  { id: 1, kind: "pdf", pageNumber: 1 },
  { id: 3, kind: "blank", width: 600, height: 800 },
  { id: 2, kind: "pdf", pageNumber: 2 },
]
```

この場合、画面の2ページ目はID 3。書き込みは`strokesByPage[3]`・`textsByPage[3]`へ保存する。元PDFの2ページ目は表示が3番目になってもID 2のままで、既存の書き込みを移動・複製しない。

元ページは1〜Nを元の順序で1回ずつ含める。白紙IDは元ページ数より大きく、現在あるIDの最大値＋1を使う。Undo／Redoは同じIDを復元する。旧ノートは`pages`がない場合に元PDF順と解釈する。開いただけで書き込みや保存内容を変換しない。

合計10,000ページまで。白紙の各辺は0より大きく14,400ポイント以下とし、それを超える表示寸法のページからの追加はエラーで停止する。重複ID・元ページの欠落や並び替え・不正寸法・構成にない書き込みIDを拒否する。PDF解析時には実際の元ページ数も照合する。

## 保存・書き出しとの接続

| 経路 | 内容 |
| --- | --- |
| IndexedDB | 線・文章・ページ構成を同じ更新番号／トランザクションで保存。元PDFは初回だけ保存する。 |
| 自動保存 | 挿入もDirtyとし、保存中のUndoや追加編集は次のスナップショットへ送る。失敗時は内容を残して再試行できる。 |
| 単体／フォルダ／選択ZIP | ページ構成を含む場合はバックアップ版3。元PDFと編集情報を保持し、コピーとして復元する。旧版1・2も読み込む。 |
| Drive単体／一括手動保存 | ページ構成付きは編集JSON版2。旧版1も読み込む。元PDFが同一なら既存のチェックサム照合でPDF再送を省く。 |
| Driveコピー | 白紙の配置・寸法も重複判定へ含める。異なる構成を同じノートとしてスキップしない。 |
| PDFダウンロード | 出力用PDFにだけ白紙を挿入し、ページIDに対応する線・文章を描く。未記入の白紙も含む。 |

IndexedDBは版3へ更新する。ストアや既存本文は変更せず、版1からの場合だけ従来の一覧情報移行も行う。古いタブを閉じて更新版を開く。サイトデータの削除・手動初期化は不要。古いコードがページ構成を失った状態で再保存することを防ぐため、版2以下での再接続は拒否する。バックアップ版3・Drive JSON版2も、古いアプリでは未対応形式として拒否される。

通常の自動保存先はブラウザ。Drive自動同期・正式保存への切り替え・500MBキャッシュ整理を今回実装したものとは扱わない。

## コードの役割

- `notePages.ts`／`types.ts`：ページ構成、サイズ・ID・元ページ順と書き込み先の検証、挿入。
- `PdfWorkspace.tsx`／`PdfPage.tsx`：追加ボタン・表示順からページIDへの変換・白紙描画。編集レイヤーは既存のものを共用する。
- `strokeHistory.ts`／`localAutosave.ts`／`localNotes.ts`：ページ構成を履歴・自動保存・再読込・復元へ含める。
- `noteBackupData.ts`／`noteBackupFile.ts`：新旧形式の検証と構成を保持したZIP化。
- `googleDriveNoteData.ts`／`googleDriveNotes.ts`／`noteDuplicates.ts`：Drive形式・手動保存／読込と重複判定。
- `exportAnnotatedPdf.ts`：元PDFを保持したまま、出力に白紙とその書き込みを追加する。

## 実機で残る確認

利用者から基本操作はできていそうとの報告あり。追加アイコンの分かりにくさはUI調整時に見直す。以下の全ケースを確認済みとは扱わない。

自動検証はfake-indexeddb・代用通信・Reactイベント接続・実PDF解析を使用する。ユーザーのブラウザDB・実Google Driveは変更しない。実機・公開環境では次を確認する。

1. 既存の複数ページノートで途中・末尾へ追加し、以前のメモが元のページに残る。
2. 白紙に線・マーカー・文章・付箋を追加し、部分消去・Undo／Redoを試す。挿入自体のUndo／Redoも試す。
3. 保存完了後に再読み込みし、ページ順とメモが残る。新規PDFは追加だけでも一覧に保存される。
4. 単体・フォルダ・選択ZIPを保存・復元し、白紙上のメモを再編集する。
5. Driveの単体／一括手動保存・同名上書き・コピーを試す。同一の再コピーで重複せず、白紙が異なる内容は復元される。
6. PDFをダウンロードして、回転PDF・横長白紙・未記入白紙・日本語メモが正しい順序とサイズで含まれる。
7. PC・スマホ縦横・iPadで、追加ボタンとページ移動・描画・拡縮を確認する。
