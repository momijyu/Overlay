# ページ見出し（第5回）

2026年11月5日の変更：ページ見出しの入力欄・一覧を通常画面から削除し、資料・ページを探す入口は付箋一覧へ統一した。保存済みの見出しは互換データとして保持し、通常編集・保存・バックアップ・Drive経由でも消さない。以下のページ見出しの操作説明は以前の仕様。

2026年11月5日の追加で、現在のDB版は5。付箋一覧用の参照を再生成し、既存PDF・本文・独立した見出しは保持する。[付箋一覧](./sticky-outline.md)。以下の旧版への記述は機能追加時点の記録。

## 操作

1. PDFを開き、見出しを付けたいページへ移動する。
2. 左上の三本線からメニューを開き、「ページ見出し」を展開する。
3. 見出しを入力して「適用」またはEnterで確定する。最大120文字・改行なし。前後の空白は取り除く。IME変換中のEnterでは確定しない。
4. 見出し一覧の行を押すと、そのページへ移動してメニューを閉じる。

現在のページの見出しは同じ入力欄で変更できる。「キャンセル」は入力を確定前へ戻す。「見出しを削除」または空欄の適用で削除する。ページを移動した場合、未確定の入力は破棄する。閉じて開き直すだけなら、同じページ・確定値の間は入力を保持する。全ページへの入力は不要で、書き込みのないページ・追加した白紙にも付けられる。

一覧には見出しのあるページだけを現在の表示順で並べ、表示ページ番号を添える。入力欄と一覧は既存のノート用メニュー内にまとめ、編集領域へ常設しない。

## 保存と履歴

見出しは元PDFに書き込まず、`headingsByPage: Record<number, string>`で安定したページIDへ結び付ける。白紙を途中へ挿入して表示番号が変わっても、見出しは元のページに残る。旧ノートの未定義は空と解釈し、開いただけでは変換・保存しない。

適用・削除後は線・文章・ページ構成と同じスナップショット・更新番号で自動保存する。見出しだけでも初回保存の対象になる。保存中の変更は順番に保存し、失敗時は画面と履歴を残して再試行する。草稿、一覧の開閉、ページ移動は保存・履歴を増やさない。

確定・削除は線・文章・白紙追加と共通の直近100操作のUndo / Redoへ渡す。取り消し・やり直しで対象ページへ移動し、結果も自動保存する。ノート切り替え・再読み込みで履歴はリセットする。

## 保存形式と互換性

| 保存経路 | 見出しの扱い |
| --- | --- |
| IndexedDB | DB版4。ストアと既存PDF・本文は書き換えない。通常保存トランザクションに含める。 |
| 単体／フォルダ／選択ZIP | 見出しを含む場合はバックアップ版4。元PDF・ページ構成・編集情報とともに復元する。旧版1〜3も読み込む。 |
| Drive単体／一括手動保存 | 見出し付きは編集JSON版3。旧版1・2も読み込む。元PDFが同一なら見出し変更だけではPDFを再送しない。 |
| 重複復元の判定 | 見出しも比較する。同じPDF・書き込みでも見出しが異なる場合は別内容と扱う。 |
| PDFダウンロード | 見出しは印字せず、PDFしおりも追加しない。編集可能な情報を保管する場合はバックアップを使う。 |

見出しのない出力は従来形式を維持する。古いアプリは新形式を拒否するので、更新版で読み込む。DB版4更新後は古いタブの再接続を拒否し、古い履歴から新しいメタデータが失われることを防ぐ。更新時は古いタブを閉じる。サイトデータの削除・初期化は不要。

ページIDの形式、最大10,000項目、文字列・文字数・制御文字を検証する。ページ構成がある場合はそのIDと照合し、実PDFを開くとき・バックアップ解析時・Drive読込時は実際の元ページ数とも照合する。不正な参照を持つデータは保存／復元を完了させない。

## 主なコード

- `pageHeadings.ts`：文字列・ページIDの検証、追加・変更・削除を行う。
- `components/PageHeadingsPanel.tsx`：現在ページの入力と、表示順の見出し一覧を表示する。
- `components/PdfWorkspace.tsx`・`strokeHistory.ts`・`localAutosave.ts`：ページ移動、混在履歴、確定した内容の保存を接続する。
- `localNotes.ts`・`noteBackupData.ts`・`noteBackupFile.ts`・`noteDuplicates.ts`：保存・復元・形式検証と重複判定へ見出しを含める。
- `googleDriveNoteData.ts`・`googleDriveNotes.ts`：Drive編集JSONの検証・手動保存・読込へ反映する。

## 残る確認

自動テストは隔離したDB・代用通信とイベント接続で検証し、利用者の実データを操作しない。実機では追加→変更→一覧移動→白紙挿入→Undo / Redo→開き直し→バックアップ／Drive復元を確認する。スマホ・iPadと公開環境の確認は未完了。

今回の実装は見出しのみ。次はDrive自動保存・未送信保護・500MBキャッシュ整理、その後に保留中のアイコンやDrive画面を含むUI調整・通し確認へ進む。通常の自動保存先は引き続きブラウザ内で、Driveへは手動保存する。
