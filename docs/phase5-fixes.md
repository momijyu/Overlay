# 第5回：不具合と潜在エラーの確認

2026年11月5日。Antigravityの指摘を現行コードと照合し、Drive階層連携で追加確認した不具合も修正した。実データを使わず、代用Google API・隔離したIndexedDB・生成したPDFで検証する。

## 修正内容

| 対象 | 対応 |
| --- | --- |
| `package.json` | 本番ビルドを`next build --webpack`へ変更。`type: module`を明示し、テスト実行時のモジュール形式の再判定警告を解消する。開発サーバーの起動方法は変更しない。 |
| `PdfWorkspace.tsx`・`public/pdfjs/` | インストール済みPDF.jsと同じ版の標準フォントとライセンスを同梱し、`standardFontDataUrl`を指定する。外部CDNには依存しない。 |
| `exportAnnotatedPdf.ts` | ページに収まるテキスト・付箋は下端を超えない位置へ出力時だけ補正する。保存内容は変えず、文章自体がページより高い場合のエラーは維持する。 |
| `googleDriveBatch.ts`・`GoogleDriveBatchSave.tsx` | 選択内の同名ノートはID付きの保存名を表示し、別々に保存する。120文字上限と他の保存名との衝突を考慮する。元ノート名は変更せず、上書き対象の確認は維持する。 |
| `googleDriveClient.ts` | Overlay専用フォルダの重複時は自動選択・統合せず、使用するものをマイドライブ直下に1つ残し、他は別の場所へ移して再接続する手順を表示する。データ削除は求めない。 |
| `TextBoxEditor.tsx` | 外側クリック・終了時などのリスナーはマウント時だけ登録する。参照を通して最新の確定処理を呼び、文章・サイズ・IME保護を維持する。 |
| `PdfPage.tsx` | 描画倍率のViewportを計算と描画で共有する。元サイズ取得用のscale:1は維持する。 |
| `PdfWorkspace.tsx` | 親要素とボタンで重複していた`desktop-only`を整理する。PCでの出力欄は維持する。 |

Turbopackの報告された内部エラーを、アプリのCSS不正と断定していない。今回はインストール済みNext.jsのCLI資料でサポートされるwebpack指定へ切り替え、本番ビルドの回避策とした。Turbopack自体の根本原因を修正したものではない。

## Drive階層連携の回帰修正

- 別端末で閲覧しただけのノートを、別ノートの保存や再接続で送信対象にしない。初回接続時の既存ノート登録は維持し、その後は本文を保存したノートと新たに復元したノートだけを登録する。
- 通常の本文更新では一覧・階層の全件走査を行わない。対象ノートの内容・一覧参照・送信待ちは同じトランザクションで更新する。新規追加・名前変更・移動・削除では引き続き階層変更を記録する。
- 複数の本文版がある場合、バックアップには利用者が選んで取得済みの版を使用する。未選択なら勝手に選ばず、対象ノートを開いて版を選び、再実行するよう案内する。未送信の編集内容は保持する。
- 別端末の初回本文送信待ちノートは一覧にまだ載らなくても、親フォルダの削除判定では存在するものとして扱う。単独・一括どちらの削除も送信完了まで拒否し、親だけが消えて同期不能になることを防ぐ。

## 意図した仕様として維持する項目

- スマホUIの判定には既にタッチ操作の条件があり、横向き専用の配置も実装済み。今回の幅だけという指摘は現行コードには該当しない。
- 未編集・保存済みの常時表示は、利用者指定により非表示。保存中・失敗・再試行は残す。
- ページ見出しUIは利用者指定で削除済み。付箋一覧を入口とし、既存見出しデータと互換処理は保持する。`PageHeadingsPanel`は通常画面へ戻さない。

## 検証と残る確認

自動テストでは、閲覧用キャッシュの非登録、送信待ちの子があるフォルダ削除の拒否、複数版のバックアップ、通常保存での全件走査なし、同名の別保存と元データ保持、標準フォントの読み込み指定、下端のPDF出力、リスナーの再登録なしと最新草稿の確定を確認する。

実Google・スマホ／iPad・公開環境での通し操作と所要時間の計測は別途必要。APIの通信回数やGoogle側の応答時間を今回の変更で保証しない。利用者のブラウザデータ・Google Driveは操作せず、サーバー起動／停止・ポート変更・commit・pushも行わない。検証コマンドの結果は[第5回の確認記録](./phase5-checks.md)へ記録する。
