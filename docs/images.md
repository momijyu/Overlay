# 画像の挿入

2026年11月13日の利用者指定で追加した。画像の順番は画像同士で変更でき、画像全体はペン・図形・文章・付箋の背面に固定する。

## 操作

1. PDFまたは白紙を開き、画像のアイコンを選ぶ。
2. 設定行の「画像・PDFを追加」からPNG・JPEGまたはPDFを選ぶ。スマホでは画像ツールを選ぶと設定を開く。
3. 画像内をドラッグして移動、選択枠の右下をドラッグして縦横比を保った拡縮を行う。ページからはみ出さない範囲に制限する。
4. 選択中の「90°回転」「切り抜き」「前へ」「後ろへ」「画像削除」で編集する。「前へ／後ろへ」は画像同士の重なり順。

切り抜きは上下左右の範囲を調整し、「適用」で確定する。元画像は変更せず、後から範囲を戻せる。キャンセル・Escapeでは変更しない。移動・拡縮は指やマウスを離した時に確定し、中断・二本指操作では確定しない。追加・移動・拡縮・回転・切り抜き・重なり変更・削除は既存のUndo／Redoと自動保存へ渡す。画像追加だけでも初回保存を開始する。

見開きでは選択した側に設定を表示し、編集先を固定ページIDで管理する。画像読み込み中にノート・ページ・道具を切り替えた場合、別のページへ追加しない。

移動・拡縮中に道具・倍率・ページ寸法・編集内容が変わった場合や操作が無効になった場合は、途中の位置を確定しない。切り抜きの草稿も同じ条件で破棄し、道具を戻しても古い草稿を復活させない。

## 画質と上限

- 画像ファイルは静止PNG・JPEGに対応し、PDFは選んだ1ページをPNGへ変換する。HEIC・WebP・アニメーションPNG等は変換を案内する。専用のカメラ撮影・クリップボード画像貼り付けは今回追加しない。
- 通常は元ファイルのバイト列を保持し、自動縮小・再圧縮はしない。JPEGの向き情報がある場合は、ブラウザが補正した同じ画素数のPNGへ正規化する。この場合は容量が増えることがある。
- 1画像は20MiB以下・1,600万画素以下・一辺8,192px以下。ノート全体の元画像は64MiB以下・3,200万画素以下、配置は40個まで。同じ元画像の再利用は容量を重複加算しない。
- デコード前に形式と寸法を検査し、上限超過は既存内容を変更せず拒否する。処理後はImageBitmapを閉じ、表示用Object URLも解放する。
- 表示・拡大・切り抜きによって元画素が増えることはない。小さい元画像を大きく表示した場合の粗さは残る。

## 保存・復元

`imageData.ts`で元画像のSHA-256・形式・寸法と配置を扱う。配置はページID、元画像ID、正規化した位置・寸法、90度単位の回転、切り抜き範囲だけを持つ。元画像は不変のBlobとして分離し、JSONへBase64を埋め込まない。Undoの各操作にも元画像バイト列を複製しない。

- **IndexedDB**：ノートの配置と元画像Blobを保存する。DB版を8へ上げ、旧ノートは画像なしで開く。更新時に画像が省略された既存の呼び出しは元画像を保持し、明示的な画像解除はUndoを含め反映する。ノート削除で画像も除去する。
- **編集用バックアップ**：画像入りは形式版5。配置はmanifest、元画像はZIP内の`images/<SHA-256>.png`または`.jpg`へ格納し、同じ元画像を共用する。サイズ・参照・ハッシュ・ヘッダーを検証し、欠落・改変・余分なエントリーは拒否する。既存の合計256MiB上限は元PDFと画像を含む。
- **Google Drive**：画像入り本文は形式版5。元画像はノートの保存先へ別ファイルで送信し、本文から参照する。画像の所有者・保存先・参照・サイズ・Google算出チェックサムを確認する。同じ保存先の検証済み元画像は再利用し、移動・ペン入力ごとに再送しない。画像取得を含む読み込み中の本文更新は採用を中止する。認可・未送信・競合保護は維持する。
- **キャッシュ**：画像のバイト数もノートのキャッシュ容量へ含める。未送信・使用中等の保護条件は変更しない。
- **PDF出力**：`exportImages.ts`で元画像を埋め込み、配置・回転・切り抜き・画像同士の順番を反映した後、ペン・文章等を描画する。同じ画像は1回だけ埋め込み、白紙・指定ページ出力にも対応する。元PDFは変更しない。

画像を削除した場合は現在の保存内容から未使用Blobを外す。Undo用の参照は履歴がある間保持する。Drive上の過去の画像実体は旧版が参照する可能性があるため自動削除しない。古いアプリで画像入りノートを編集すると画像情報を扱えないため、受け渡す端末も更新版を使う。

## 今回の対象外と確認待ち

画像を含む投げ縄・複製ショートカット、ペンと画像を交互に並べるレイヤー管理、明るさ等の加工、HEIC変換は拡張候補。表示中ページの種類別一括消去は従来どおり線・付箋・テキストを対象とし、画像は「画像削除」から消す。ページ削除では対象ページの画像も除き、Undoで戻せる。

自動テストではローカル保存、画像入りZIP、仮APIのDrive保存・再取得・変更検知、操作の中断、実PDFの描画結果を確認する。実スマホ・iPad・公開環境・実Google Driveでの確認は未完了。実通信の速度向上や、あらゆる画像形式・端末での画質の一致を保証したものではない。

## PDFの1ページを画像として追加（11月15日）

「画像・PDFを追加」でPDFを選ぶとページ選択画面を開く。ページ番号の入力・前後ボタンでプレビューし、「追加」で表示中の1ページだけを配置する。読み込み・変換中は追加を無効にし、キャンセルは受け付ける。途中で道具・ノート・ページ・倍率が変わった場合は古い配置を確定しない。

- 入力PDFは50MiB以下。パスワード付きPDFは解除後のファイルを案内する。破損・読み込み失敗時は既存内容を変更しない。
- PDF.jsで144dpi（倍率2）を基準に変換し、長辺4,096px・800万画素に収める。画面倍率や端末の解像度では変換サイズを変えない。大きいページは解像度が下がるため、元PDFのベクター品質を維持する方式ではない。
- PNGが20MiBを超えた場合と、既存のノート画像容量・画素・配置数の上限超過は挿入を拒否する。変換キャンセル時は描画タスクを中断し、canvas・表示URL・PDF読み込みタスクを解放する。
- 保存するのは選んだページのPNGと画像の配置情報。挿入元PDF全体は保存せず、文字の選択・検索はできない。通常の画像と同じ回転・切り抜き・前後変更、Undo／Redo、IndexedDB、編集用バックアップ、Drive、PDF出力を利用する。DB／本文の形式版は変更しない。
