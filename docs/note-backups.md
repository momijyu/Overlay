# 編集用バックアップ（2026年10月25日）

第4回の追加機能。普段の保存先はIndexedDBのままで、Google連携は行わない。閲覧用のPDFダウンロードと、再編集可能なバックアップを分ける。

## 操作

複数選択のZIP保存：一覧の「選択」でノート・フォルダへチェックを付け、「ZIPで保存」を押す。`Overlay-選択項目.zip`をダウンロードする。読み込みは一覧上部の「バックアップを読み込む」からこのZIPを選ぶ。解凍は不要。PC・スマホで同じ操作を使う。「全選択」で一覧全体も指定できる。

選択したフォルダのチェックは子孫にも付く。親子を同時にチェックしても同じノートは1件だけ含める。チェックされていない親フォルダは含めず、そこから選んだ単独ノート・フォルダはZIP内の一番上へ置く。選択フォルダ内の階層・空フォルダは維持する。一部の子を外した場合は既存の選択ルールにより親も外れる。出力直前に最新一覧を検証し、対象が消えた場合や、選択フォルダに未チェックの子が増えた場合は一覧の更新・選び直しを求める。未選択の新しい子は勝手に追加しない。

異なる親にある同名の根フォルダも選べる。ファイル内では元名を残し、復元時に既存の根フォルダとZIP内の別の根の両方を見て復元番号を付ける。既存ノート・フォルダは上書きしない。

以前の単体・フォルダの書き出しも維持する：

1. 単独ノートは、PCの「ノートのバックアップ」またはスマホの「… → ノートのバックアップ」から書き出す。一覧の「操作」からも選べる。
2. フォルダは一覧で対象を選び、「操作 → フォルダのバックアップ」。対象フォルダと子孫・空フォルダを含む。外側の親・他のノートは含めない。
3. 一覧上部の「バックアップを読み込む」で`.overlay`または選択出力の`.zip`ファイルを選ぶ。解凍は不要。解析だけではDBへ保存しない。一般のZIPや別アプリのバックアップは対象外。
4. 名前・ノート件数・フォルダ件数を確認し、「復元」でコピーを追加する。キャンセル・背景・Escapeは追加しない。
5. 一番上へ追加したノートやフォルダを開く。同名の根フォルダには「（復元1）」等が付く。同名ノートは別IDなので共存する。

復元中の失敗は全件取り消し、確認画面とエラーを残す。現在の編集画面・履歴は切り替えず、成功後は一覧だけを更新する。元のノート・OS上の元ファイルは変更しない。

## 共通データとファイル形式

`NoteBackup`は単体・フォルダ用の`schemaVersion:1`・`kind:note|folder`、選択ZIP用の`schemaVersion:2`・`kind:selection`を扱う。名前、フォルダ配列、ノート配列を持つ。各ノートには元PDFのBlob、名前、元ファイル名、所属、全ページの`strokesByPage`・`textsByPage`を保持する。ペン・マーカーの色と太さ、テキスト・付箋の文字サイズ・色・背景・旧ボックス寸法も維持する。旧ノートの文章未定義は空として扱い、以前の`.overlay`も引き続き読める。

ファイルは無圧縮ZIPを`.overlay`拡張子で出力する。追加した[fflate](https://github.com/101arrowz/fflate) 0.8.3（MIT）は梱包・読み込みだけを担当し、バックアップ操作時に遅延ロードする。PDFを再圧縮せず、Base64にも変換しない。導入版の[ライセンス全文](../public/licenses/fflate-LICENSE.txt)を公開サイトの`/licenses/fflate-LICENSE.txt`にも同梱する。

```text
manifest.json       app:Overlay、schemaVersion、階層・名前・編集情報・各PDFのCRC32
manifest.crc        manifest.jsonのCRC32（8桁の16進文字列）
pdfs/0.pdf          ノート配列の0番目の元PDF
pdfs/1.pdf          次の元PDF（フォルダバックアップの場合）
```

元のノート名・フォルダ名をZIPのパスに使わない。CRC32は偶発的な破損の検出であり、暗号化・電子署名・改ざん防止ではない。ファイルには元PDFとメモが含まれるため、他人へ渡す場合は内容を確認する。

将来のGoogle Drive実装でも、この共通データと検証処理を再利用できる。Drive上のフォルダ配置、OAuth、差分保存、オフライン、競合処理は今回作っていない。DriveがZIPを必須とする設計ではない。

## 各ファイルの責務

- `noteBackupData.ts`：共通型、形式バージョン、名前・ID・階層・循環・同名衝突・線・文章の検証、安全上限、出力名。
- `noteBackupFile.ts`：ZIP梱包／解析、CRC32、実PDFの解析と編集ページの検証。保存先には依存しない。
- `localNotes.ts`：単体・フォルダと、`captureSelectedNoteBackup`による選択項目のスナップショットを同一readonlyトランザクションで取得。復元はIDを全て振り直し、`folders`・`pdfs`・`notes`を1つのreadwriteトランザクションで追加する。書き込み失敗時は全件ロールバックする。
- `PdfWorkspace.tsx`：処理中の編集ロック、ファイル出力、読み込み確認、復元後の一覧更新、エラー表示。開いているノートは画面で確定済みの最新スナップショットを渡し、通常保存の容量不足時にも持ち出せる。
- `NotebookSidebar.tsx`・`NotebookDrawer.tsx`：対象ノート／フォルダの書き出し、読み込み選択欄。`NotebookRestoreDialog.tsx`：件数確認・キャンセル・失敗表示。

フォルダ出力は現在の自動保存を待ち、失敗時は古いデータを黙って出さず中止する。この場合、開いているノートの単体バックアップは可能。入力中の草稿は既存の外側クリック確定を使い、変換中・不正な入力は確定しない。未完了の線・消去・ドラッグもバックアップへ含めない。

## 安全上限・対象外

1ファイルにつき合計256MiB、200ノート、1000フォルダ、編集JSON16MiB、50万座標点、1万テキスト／付箋、階層深さ100。元PDFは各1〜1万ページ。これは通常のIndexedDB保存容量ではなく、一度の読み込み・解析の安全上限。大きいフォルダは小分けに書き出す。スマホ等で上限付近のファイルを扱えることは保証しない。

入力サイズを読み取り前に確認し、無圧縮かつ想定パス・件数・サイズのZIPだけを展開する。圧縮ZIP、パス逸脱、重複パス、不足／余分なPDF、未知の版、破損、循環、不正座標・文章、ページ参照の不一致、暗号化PDFを拒否する。PDF解析・検証はDB書き込み前に完了させる。

履歴・草稿・表示倍率・前回ページ、OS実フォルダへの直接保存、Supabaseデータ移行、Google連携、自動バックアップ・同期は対象外。全ライブラリ専用の別ボタンは作らず、必要なら「全選択 → ZIPで保存」を使う。PDFだけの書き出しから元の編集オブジェクトを取り戻す機能ではない。

- 子孫・空フォルダを含むテスト用フォルダをバックアップする。
- 複数のノートとフォルダをチェックし、「ZIPで保存」で出力、選択外のノートは含まず、同じZIPから件数・階層・編集状態を復元できることを確認する。同名で親が違うフォルダも確認する。
- 実データを消さず、別ブラウザ等の隔離した環境へ読み込む。キャンセルで追加されず、復元後はコピーが現れることを確認する。
- 色・位置・文字サイズ・階層を確認し、消しゴム・文字編集・自動保存・再読み込み・PDF出力を確認する。復元ノートのUndoは復元後の編集から始まる。
